## 🖥️ Simulation Experiment Specifications

In simulation mode, the swarm navigates virtual gas plumes generated by GADEN. Quadcopters use Software-in-the-Loop (SIL) controllers to simulate firmware behavior.

### 🗂️ Nodes Overview

| Node | Source File | Role |
|---|---|---|
| `/cf1`, `/cf2`, `/cf3` | `APF_1_1_agent.py` | Decentralized path planning agents |
| `/GSLenvironment` | `APF_1_1_env.py` | Centralized physics server (forces, bout maps) |
| `/mox1`, `/mox2`, `/mox3` | `simulated_gas_sensor.cpp` | Simulated gas sensors querying GADEN concentrations |
| `/world_to_map_static_tf` | — | Publishes static `world` → `map` coordinate frame |
| `/crazyflie_server` | `crazyflie_server.py` | Simulates firmware APIs (takeoff, land, velocity) |
| `/gaden_environment` | `environment.cpp` | Simulates 3D room structure and obstacle occupancy |
| `/gaden_player` | `player.cpp` | Replays spatial gas distributions |
| `/rviz2` | — | Renders maps, drone trajectories, and visual markers |

### 🔍 Node Details: Publishers, Subscribers & Services

#### A. 🚁 Drones `/cf1` to `/cf3`
> **Source**: [`APF_1_1_agent.py`]

##### Publishers
| Topic | Message Type | Description |
|---|---|---|
| `GSL/bouts/cf[ID]` | `geometry_msgs/msg/Point` | Broadcasts positions of detected gas concentration bouts |
| `/cf[ID]_setpoint` | `visualization_msgs/msg/Marker` | Renders the drone's current target destination in RViz |
| `/cf[ID]_resultant` | `visualization_msgs/msg/Marker` | Renders the combined attractive + repulsive velocity vector |
| `/cf[ID]_attraction` | `visualization_msgs/msg/Marker` | Renders the attractive force vector |
| `/cf[ID]_repulsion` | `visualization_msgs/msg/Marker` | Renders the repulsive force vector (wall/traffic avoidance) |
| `/cf[ID]_mode` | `visualization_msgs/msg/Marker` | Displays active navigation mode (Exploration vs. Exploitation) |

##### Subscribers
| Topic | Message Type | Description |
|---|---|---|
| `/mox[ID]/Sensor_reading` | `olfaction_msgs/msg/GasSensor` | Reads simulated gas concentrations from the virtual sensor |
| `/tf` / `/tf_static` | `tf2_msgs/msg/TFMessage` | Receives state estimations and coordinate frames |

##### Services Called (Client)
| Service | Class |
|---|---|
| `GSL/GetForces` | `gaden_simulation_interfaces/srv/GetForces` |

## 🛸 Physical Experiment Specifications

In physical flight, drones navigate a real workspace. Position tracking uses the **Loco Positioning System (LPS)**, and gas concentrations are logged directly from onboard **SGP30 MOX** gas sensors.

### 🗂️ Nodes Overview

| Node | Source File | Role |
|---|---|---|
| `/cf1`, `/cf6`, `/cf8` | `APF_Field_1_agent.py` | Decentralized physical drone path planning agents |
| `/GSLenvironment` | `APF_Field_1_env.py` | Centralized physics server (boundary & collision forces) |
| `/world_to_map_static_tf` | — | Publishes static `world` → `map` coordinate frame |
| `/crazyflie_server` | `crazyflie_server.cpp` | C++ ROS 2 bridge communicating via Crazyradio PA dongles |
